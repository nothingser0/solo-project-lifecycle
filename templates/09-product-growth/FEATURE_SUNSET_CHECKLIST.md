# Feature Sunset & End-of-Life (EOL) Checklist

> **Module**: M13 (Product Operations & Continuous Iteration)  
> **Trigger**: Feature usage $< 5\%$ over 60 days, disproportionate maintenance cost, or statutory/third-party API deprecation.  
> **Objective**: Safely decommission features without data loss, broken API contracts, or customer churn.

---

## 1. Feature Sunset Metadata

| Field | Value |
| :--- | :--- |
| **Feature Name** | `[e.g., Legacy CSV Auto-Sync / SMS Notification Channel]` |
| **Deprecation Reason** | `[Low adoption (<2%) / Replaced by Webhooks / Provider Cost]` |
| **Target Deprecation Date** | `YYYY-MM-DD` |
| **Target Hard Teardown Date**| `YYYY-MM-DD` (Min. 30 days post-deprecation) |
| **Owner (Solo Dev)** | `[Your Name]` |

---

## 2. Phase 1 — Impact & Dependency Analysis

- [ ] **Usage Audit**: Identified all active users/tenants utilizing the feature in the past 90 days (`COUNT(DISTINCT user_id)`).
- [ ] **API Contract Check**: Verified whether public API endpoints, webhooks, or mobile apps rely on this functionality.
- [ ] **Data Retention Requirements**: Confirmed statutory retention period under UU PDP / Tax regulations (e.g., financial records must be archived for 5–10 years).
- [ ] **Alternative Path**: Determined migration path for existing users (e.g., manual export, upgrade to new feature, or alternative third-party tool).

---

## 3. Phase 2 — Communication & Grace Period (T-30 Days)

- [ ] **In-App Notification**: Non-blocking deprecation banner displayed to active users of the feature.
- [ ] **Direct Outreach / Email**: Sent explanatory notice detailing the sunset timeline, rationale, and export instructions.
- [ ] **Export Self-Service**: Provided 1-click self-service export (JSON/CSV) for all historical data generated by the feature.
- [ ] **Documentation Update**: Marked relevant user manual guides and API docs with `[DEPRECATED - EOL: YYYY-MM-DD]`.

---

## 4. Phase 3 — Soft Deprecation (Read-Only Mode)

- [ ] **Disable Creation**: Disabled buttons, UI inputs, and POST/PUT endpoints for creating new records under this feature.
- [ ] **Graceful Read Access**: Retained GET endpoints and read-only views for existing records.
- [ ] **API Warning Header**: Injected `Sunset: <date>` and `Deprecation: @<timestamp>` HTTP response headers (RFC 8594).
- [ ] **Error Handling**: Configured human-readable error messages for blocked actions:
  ```json
  {
    "error": "feature_deprecated",
    "message": "This feature was sunset on YYYY-MM-DD. Please use [Alternative] or export your historical data."
  }
  ```

---

## 5. Phase 4 — Hard Teardown & Code Cleanliness (T-0 Days)

- [ ] **Database Archival**: Dumped historical feature tables into cold backup storage (e.g. compressed S3 Glacier / R2 archive).
- [ ] **Database Migration**: Dropped deprecated columns/tables via a forward-only migration script (`down` rollback documented).
- [ ] **Code Deletion**: Removed dead frontend routes, components, and backend controller actions (zero leftover commented code).
- [ ] **Background Job Cleanup**: Removed scheduled cronjobs, queue workers, and event subscribers tied to the feature.
- [ ] **Secrets & Config Cleanup**: Revoked unused third-party API credentials, environment variables, and webhook subscriptions.
