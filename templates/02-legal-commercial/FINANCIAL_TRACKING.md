## Cost Control Measures

### When Budget Reaches 75% (Month 6)

**Actions**:
1. Freeze new features (scope lock)
2. Review remaining work (estimate hours)
3. Escalate if overrun projected
4. Use contingency if approved

---

### If Budget Overrun Projected

**Options**:
1. **Reduce Scope**: Defer nice-to-have features to Phase 2
2. **Request Budget Increase**: Requires client approval
3. **Absorb Cost**: Company eats overrun (avoid if possible)

**Escalation**: Project Sponsor → Client Steering Committee → Executive approval

## Expense Tracking

### How to Log Expenses

**Time Tracking**:
- Tool: Jira, Harvest, Toggl
- Required fields: Date, hours, task, notes
- Frequency: Daily (end of day)
- Approval: Team lead reviews weekly

**Example Entry**:
```
Date: 2024-04-15
Project: MyApp
Task: Build payment integration
Hours: 6
Rate: $140/hr
Total: $840
Notes: Implemented Stripe checkout flow
```

---

### Infrastructure Costs

**Automated Tracking**:
- AWS Cost Explorer (daily reports)
- Datadog billing dashboard
- Monthly invoice reconciliation

**Monthly Review**:
- Compare actual vs budget
- Identify cost spikes (investigate)
- Optimize if over budget (right-size instances)

## Financial Reporting

### Weekly Status Report (to PM)

**Format**: Spreadsheet or Jira dashboard

**Contents**:
- Hours logged this week (by role)
- Total spend this week
- Cumulative spend vs budget
- Forecast to completion

---

### Monthly Financial Report (to Sponsor)

**Format**: PDF or slide deck

**Contents**:
1. Executive Summary (budget status, risks)
2. Budget vs Actual (table + chart)
3. Burn Rate (trend over time)
4. Forecast to Completion
5. Risks & Mitigation (if overrun projected)
6. Payment Status (invoices sent/received)

**Example**:
```
MONTHLY FINANCIAL REPORT - April 2024

Budget Status: ⚠️ Warning (42% spent, 50% time elapsed)

Budget: $500,000
Spent: $210,000 (42%)
Remaining: $290,000 (58%)

Burn Rate: $52,500/month
Forecast: $420,000 (16% under budget)

Risks:
- Payment integration took 20% longer than estimated (+$10k)
- Mitigation: Reducing QA hours in later phases (-$10k)

Payment Status:
- M1-M3 received: $300,000
- M4 invoice sent: $100,000 (pending)
```

## Budget Variance Analysis

### Why Track Variance?

**Purpose**: Identify trends early, adjust course

**Variance Types**:
- **Favorable**: Spending less than budgeted (good)
- **Unfavorable**: Spending more than budgeted (bad)

---

### Example Variance Analysis

**Labor Variance**:
```
Budgeted: $150,000 (4 months × $37,500/mo)
Actual: $180,000
Variance: +$30,000 (unfavorable)

Root Cause:
- Payment integration complexity (underestimated)
- Added 200 hours senior dev time

Mitigation:
- Use contingency budget ($30,000 available)
- Reduce scope: Defer guest checkout to Phase 2
```

### Incoming Invoices (from Vendors)

**Process**:
1. Vendor sends invoice
2. PM reviews (verify amount, services rendered)
3. Finance approves payment

## Checklist

**Project Setup**:
- [ ] Budget approved by sponsor
- [ ] SOW signed (payment terms documented)
- [ ] Financial tracking tool set up (spreadsheet, Jira)
- [ ] Time tracking tool configured (Harvest, Toggl)

**Weekly**:
- [ ] Review time entries (team members log hours)
- [ ] Calculate spend vs budget
- [ ] Update financial dashboard

**Monthly**:
- [ ] Generate financial report
- [ ] Send to sponsor
- [ ] Send milestone invoice (if milestone complete)
- [ ] Review burn rate, forecast

**At Risk**:
- [ ] Escalate to sponsor if >10% over budget
- [ ] Present mitigation options (reduce scope, add budget)
- [ ] Get approval before exceeding budget

---

## Notes

**Track everything**: Log all hours, expenses immediately

**Forecast early**: Identify overruns when 50-60% spent

**Communicate**: Surprise budget overruns destroy trust

**Use contingency wisely**: It's for unexpected costs, not poor planning
